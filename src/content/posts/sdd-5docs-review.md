`review.md`는 요약문이 아니라 완료 판정 기록이다.

## 핵심

- 실제 변경과 의도적으로 제외한 범위.
- `spec.md` 수락 조건별 검증 증거.
- 테스트와 실제 실행에서 본 결과.
- self-review에서 찾아 고친 결함.
- 미충족 조건과 남은 위험.
- LocalMind에 남긴 결정 기록.

## 완료 기준

| 확인 | 증거 |
| --- | --- |
| 새 테스트가 문제를 잡는가 | 구현 전 실패, 수정 후 통과 |
| 실제 환경에서 동작하는가 | 목표 뷰포트·원격 상태·사용 흐름 |
| 모든 수락 조건을 충족했는가 | 조건별 테스트·실측·관찰 |
| 수정 후에도 유효한가 | 최신 코드로 전체 재검증 |

## 원칙

- `확인함` 대신 실행 환경·명령·결과를 적는다.
- 검증하지 못한 조건은 미검증으로 남긴다.
- 독립 리뷰가 없었다면 비독립 검토라고 밝힌다.
- 파일만 있고 자리표시자만 남았다면 미완료다.
