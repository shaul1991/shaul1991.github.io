`plan.md`는 `spec.md`를 만족할 접근 하나와 검증 방법을 정한다.

## 핵심

- 선택: 어떤 접근을 왜 택했는가.
- 영향: 어떤 모듈·계약·데이터·화면이 바뀌는가.
- 경계: 이번에 건드리지 않을 것은 무엇인가.
- 검증: 각 수락 조건을 무엇으로 증명하는가.

## 작성 기준

| 남긴다 | 줄인다 |
| --- | --- |
| 채택한 접근과 근거 | 가능한 방법의 긴 목록 |
| 중요한 트레이드오프 | 근거 없는 구조 개선 |
| 예상 영향과 비영향 범위 | 수정 파일 목록만 적기 |
| 실패 조건과 통과 기준 | `테스트한다`는 선언 |

새 증거로 전제가 달라지면 조용히 범위를 늘리지 말고 `plan.md`를 갱신한다.

## 다음 단계
