LocalMind와 Hermes의 연결 성공 메시지만으로는 부족하다. 잘못된 지식 정본을 검색하거나 다른 기기에서 실행해도 연결 자체는 성공할 수 있다.

이 구조의 목적은 기억을 많이 넣는 것이 아니다. 사람이 소유한 기록을 올바르게 찾고, 현재 상태와 검증한 뒤, 저장소가 있는 기기에서 결과를 만드는 것이다.

## 핵심

1. **정본 확인:** `whoami`로 예상한 LocalMind와 기록 폴더가 맞는지 확인한다.
2. **검색 확인:** 식별 가능한 결정이 `brief`와 `search_notes`에서 다시 나오는지 본다.
3. **낡음 확인:** 변동성이 큰 전제를 넣고 재검증 신호가 실제 확인으로 이어지는지 본다.
4. **실행 위치 확인:** 파일, 빌드, 브라우저와 `localhost`가 어느 기기의 것인지 확인한다.
5. **결과 확인:** 성공 문구가 아니라 파일, 테스트, 화면과 diff를 직접 본다.
6. **경계 확인:** 허용하지 않은 기록 폴더와 업무 데이터가 검색·캡처되지 않는지 점검한다.

## 최소 구성

| 구성 | 책임 |
| --- | --- |
| LocalMind | 사람이 읽는 결정 기록과 검색 |
| MCP 연결 | Hermes가 기억을 찾고 남기는 통로 |
| Hermes | 현재 상태 확인, 실행, 검증 |
| 프로젝트 규칙 | 언제 검색하고 무엇을 기록할지 정의 |

한 기기에서는 로컬 연결로 충분하다. 여러 기기가 같은 기억을 쓸 때 공통 LocalMind로 확장하되, 로컬과 원격 연결이 다른 정본을 가리키지 않는지 확인한다.

## 실패할 때 확인하는 순서

검색 결과가 이상하면 모델부터 바꾸지 않는다. 정본, MCP 인증, 검색 결과, 실행 기기, 권한, 산출물 순서로 좁힌다.

첫 성공 기준은 연결 응답이 오는 것이 아니다. 과거 결정이 올바르게 소환되고, 오래된 전제가 다시 확인되며, 예상한 기기에서 만든 결과를 사용자가 직접 검증하는 것이다.
