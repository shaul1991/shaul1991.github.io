LocalMind가 공통 기억을 제공해도 모든 에이전트가 같은 권한을 가질 필요는 없다. 기억의 공유, 사용자와의 대화, 코드 실행은 서로 다른 책임이다. 나는 Hermes 프로필과 기기 경계로 이 책임을 나눈다.

기억은 모델 밖의 기록에 두고, 지식은 필요할 때 찾는다. 실행은 저장소가 있는 기기에서 하며, 원격 접근은 사용자가 허용한 범위에서만 사용한다.

## 핵심

| 역할 | 맡기는 일 | 갖지 않아도 되는 것 |
| --- | --- | --- |
| 조정자 | 의도 확인, 작업 분배, 결과 설명 | 모든 저장소의 실행 권한 |
| 구현자 | 지정된 작업 공간에서 구현과 테스트 | 사용자 메시징 자격증명 |
| 검토자 | diff와 검증 증거의 독립 확인 | 구현자의 세션 기억 |

Hermes 프로필은 설정, 세션, 스킬, 메모리와 작업 공간을 분리할 수 있다. 각 에이전트가 볼 맥락과 사용할 도구를 줄이는 데 의미가 있다.

## 권한을 넓힐 때의 기준

- 상태 조회와 파일 변경 권한을 구분한다.
- 원격 기기 접근은 사용자의 허용 뒤에 수행한다.
- 삭제, 배포, 자격증명 변경처럼 되돌리기 어려운 작업은 별도 승인을 둔다.
- 업무 기기의 코드, 로그, 고객 정보는 개인 LocalMind에 자동 저장하지 않는다.
- 사용자와 대화하는 진입점의 자격증명을 내부 작업자에게 복제하지 않는다.

에이전트 수를 늘리는 것이 목표는 아니다. 한 에이전트의 책임과 권한이 너무 넓을 때 경계를 나눈다.

## 기록도 권한을 대신하지 않는다

LocalMind에서 과거 승인을 찾았다고 현재 실행 권한이 생기는 것은 아니다. 기록은 왜 그런 선택을 했는지 알려 주고, 현재 허용 범위는 다시 확인해야 한다. 중앙 지식이 무제한 접근으로 바뀌지 않게 하는 마지막 경계는 사람과 실행 환경에 있다.
