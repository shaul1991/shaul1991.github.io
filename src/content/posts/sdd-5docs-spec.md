`spec.md`는 `goal.md`를 검증 가능한 요구로 바꾼다.

## 핵심

1. 각 요구가 어떤 목표를 지키는지 연결한다.
2. 각 요구에 수락 조건을 붙인다.
3. 답이 없는 문제는 Open question으로 남긴다.

## 작성 기준

| 항목 | 기준 |
| --- | --- |
| 기능 요구 | 목표 달성에 필요한 동작만 포함 |
| 수락 조건 | 예·아니오로 판정 가능 |
| 검증 연결 | 자동 테스트, 실측, 실행 관찰 중 하나 이상 |
| Open question | 외부 동작, 미정 정책, 갈리는 해석 |

## 제외

- 목표와 연결되지 않은 개선점.
- `모바일에서 잘 보여야 한다`처럼 판정할 수 없는 문장.
- 테스트 코드와 구현 방법의 복사.

요구가 바뀌면 코드보다 `spec.md`를 먼저 고친다.
