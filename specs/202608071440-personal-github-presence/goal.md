# Goal — 개인 GitHub 존재감 재구성

## 사용자 승인

사용자는 GitHub 프로필 저장소의 README를 "빠르게 확인할 수 있는 이력서"로, `shaul1991.github.io`를 상세 포트폴리오로 구축하는 방향을 승인했다.

## 문제

현재 GitHub 프로필 README는 개인 경력, 기술, AI 에이전시 소개가 한 화면에서 같은 비중으로 섞여 있다. 포트폴리오에서 GitHub 링크를 클릭한 채용 담당자는 김지훈이 어떤 개발자이며 어떤 문제를 해결해 왔는지 빠르게 판단하기 어렵다. 상세 경력과 사례를 담을 개인 포트폴리오 URL도 없다.

## 왜 지금인가

`https://github.com/shaul1991`을 이력서와 포트폴리오에서 대표 개발자 링크로 사용할 예정이다. 첫 화면의 정보 위계와 공개 근거를 지금 정리해야 한다.

## 성공 기준

1. GitHub 프로필 첫 화면에서 10초 안에 이름, 백엔드 역할, 4년+ 경력, 핵심 강점, 대표 성과, 공개 프로젝트를 파악할 수 있다.
2. 프로필에서 상세 포트폴리오 `https://shaul1991.github.io`로 바로 이동할 수 있다.
3. Pages 사이트에서 경력, 문제 해결 사례, 대표 개인 프로젝트, 기술 선택, 연락처를 모바일과 데스크톱에서 읽을 수 있다.
4. 공개된 모든 수치와 프로젝트 링크는 이력서 또는 현재 GitHub/실서비스에서 확인된 사실만 사용한다.
5. 두 공개 URL을 실제 브라우저로 열고 HTTP 성공, 반응형 레이아웃, 링크, 콘솔 오류를 검증한다.

## 비목표

- 전화번호 공개
- 비공개 저장소를 공개 증거 링크처럼 노출
- `www.shaul.kr`을 개인 포트폴리오로 재브랜딩
- 블로그/CMS, 관리자 화면, 분석 추적, 서버 사이드 기능
- 과장된 기술 숙련도 막대, GitHub 자동 통계 위젯, 방문자 카운터

## 제약

- 프로필 저장소는 삭제하지 않는다. 로컬 백업을 유지한 채 orphan `main`으로 이력만 초기화하고 기존 `claude/*` 브랜치를 제거한다.
- Pages는 public `shaul1991/shaul1991.github.io` 저장소로 만든다.
- Pages 구현은 빌드 의존성 없는 정적 HTML/CSS/JS를 사용한다.
- 한국어를 기본 언어로 하되 이름·직무·기술명은 자연스러운 영문 표기를 병행한다.
- 이메일은 공개하고 전화번호는 제외한다.
