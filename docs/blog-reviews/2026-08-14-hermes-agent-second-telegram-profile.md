## 독자 질문과 독립 결론

| 질문 | 결론 |
| --- | --- |
| 기존 개인 비서가 있는 상태에서 두 번째(부부 공용) Telegram 비서를 어떻게 안전하게 추가하나 | 새 이름의 프로필을 만들면 모델·credential·skill·게이트웨이·Telegram 봇이 기존 비서와 독립적으로 시작되며, 그룹 챗까지 쓰려면 `group_allowed_chats`를 별도로 설정해야 한다 |

5~7편(격리·메모리·자동화)을 읽지 않은 독자에게도 프로필 개념을 다시 설명하고, 이번 글의 범위(두 번째 프로필로 별도 비서 운영)를 명확히 한정했다.

## 근거와 검증 상태

| 범위 | 근거 | 공개 원고 표기 | 판정 |
| --- | --- | --- | --- |
| 홈서버 `couple` 프로필 존재, gateway running, 모델 조합 | 홈서버 SSH 직접 실행 (`hermes profile list`, `profile show`) | 실제 값은 특정하지 않고 "openai-codex 계열", "기존과 다른 provider 조합" 등 일반화 | 승인 |
| Telegram 봇 분리, allowed_chats/group_allowed_chats 설정 | 홈서버 config.yaml 직접 확인(민감정보 마스킹) | 실제 봇 사용자명·chat ID는 게시하지 않고 placeholder만 사용 | 승인 |
| MCP 미연결, cron 빈 상태, skill 85개/카테고리 | 홈서버 `mcp list`, `cron status`, skill 목록 직접 실행 | 관찰 사실로만 서술, 과장 없음 | 승인 |
| Gateway·cron 명령, `config set`, `mcp add` 문법 | 공식 CLI help 및 v0.20.1 문서 | source-derived 절차로 설명 | 승인 |

## 평가 항목

| 항목 | 판정 | 근거 |
| --- | --- | --- |
| 정확성 | 승인 | 모든 수치·상태(프로세스 running, MCP 미연결, skill 85개 등)는 홈서버 실행 결과에서 직접 확인 |
| 핵심성 | 승인 | 첫 문단과 핵심 표에서 "새 프로필 = 독립된 상태 공간"이라는 결론이 바로 드러난다 |
| 설명 충분성 | 승인 | 각 단계(분리 확인·대상 설정·gateway 검증·skill 검토·최종 확인)에 명령과 확인 기준이 함께 있다 |
| 해석 일관성 | 승인 | "두 번째 비서"를 새 프로필로 명확히 한정하고, DM/그룹 챗 구분을 흐리지 않는다 |
| 시각화 적합성 | 승인 | 핵심 표는 확인 항목 비교, 자주 막히는 지점 표는 증상→처리 매핑에 사용했다 |
| 중복 | 승인 | 5편(프로필) 내용을 반복하지 않고 "두 번째 프로필 추가"라는 새 시나리오만 다룬다 |
| 분량 | 승인 | guide 기준 10~15분 내 완료 가능한 5단계 구조, 불필요한 배경 설명 없음 |
| 시리즈 구조 | 승인 | 8편은 5편(프로필 개념)과 구분되는 "실제 두 번째 비서 추가" 질문에 답한다 |

## 프라이버시 검사

- 실제 봇 사용자명, chat ID, token 값: 0건 노출
- 원고 예시 명령은 모두 `<새-프로필>`, `<chat-id>` 형태의 placeholder 사용
- LocalMind 비공개 경로·개인 SSH 정보 등은 원고에 포함하지 않음
