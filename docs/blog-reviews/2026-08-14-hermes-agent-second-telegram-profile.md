## 독자 질문과 독립 결론

| 질문 | 결론 |
| --- | --- |
| 기존 개인 비서가 있는 상태에서 부부가 함께 쓰는 Telegram 비서를 어떻게 안전하게 추가하고, 실제로 무엇을 도와줄 수 있나 | 새 이름의 프로필을 만들면 모델·credential·skill·게이트웨이·Telegram 봇이 기존 비서와 독립적으로 시작되고, 문서 업로드·조건 대입·시나리오 비교를 반복하는 대화로 청약·대출 같은 다단계 자금 조사를 도울 수 있다. 그룹 대화에는 mention 기반 호출 설정으로 개입 범위를 제한할 수 있다 |

5~7편(격리·메모리·자동화)을 읽지 않은 독자에게도 프로필 개념을 다시 설명하고, 이번 글의 범위(부부용 프로필 구성 + 실사용 + 그룹 개입 제한)를 명확히 한정했다.

## 평가 항목

| 항목 | 판정 | 근거 |
| --- | --- | --- |
| 정확성 | 승인 | 모든 상태(프로세스 running, MCP 미연결)는 홈서버 실행 결과, 이사 사례와 config 변경은 세션 DB 원문에서 직접 확인 |
| 핵심성 | 승인 | 첫 문단과 핵심 표에서 "새 프로필 = 독립된 상태 공간"과 "실 사용 사례"가 바로 드러난다 |
| 설명 충분성 | 승인 | 각 단계(분리 확인·대상 설정·gateway 검증·실사용 7단계·그룹 개입 제한·최종 확인)에 명령 또는 근거가 함께 있다 |
| 해석 일관성 | 승인 | "부부용 비서"를 새 프로필로 명확히 한정하고, DM/그룹 챗 구분과 mention 제한의 의도를 흐리지 않는다 |
| 시각화 적합성 | 승인 | 핵심 표는 확인 항목 비교, 자주 막히는 지점 표는 증상→처리 매핑에 사용했다 |
| 중복 | 승인 | 5편(프로필) 내용을 반복하지 않고 "부부용 프로필 추가 + 실사용 + 그룹 개입 제한" 시나리오만 다룬다 |
| 분량 | 승인 | guide 기준 분량 상한 안에서 6단계 구조 유지, 불필요한 배경 설명 없음 |
| 시리즈 구조 | 승인 | 8편은 5편(프로필 개념)과 구분되는 "실제 부부용 비서 추가·사용·개입 제한" 질문에 답한다 |

## 프라이버시 검사

- 실제 봇 사용자명, chat ID, token 값: 0건 노출
- 부부 실명, 생년월일, 자녀 정보, 정확한 소득·보증금·대출액, 주소, 단지명, 확정 일정: 0건 노출 — 각 조사 단계의 입력 종류와 비서의 처리 방식만 일반화해 서술
- 원고 예시 명령은 모두 `failmy_bot`, `<chat-id>` 형태의 명시적 placeholder 사용
- LocalMind 비공개 경로·개인 SSH 정보 등은 원고에 포함하지 않음

## 수정 이력

1. **제목·설명 직접화** — "두 번째 Telegram 비서 운영하기"를 "부부를 위한 AI 비서 만들기"로 바꿔 대상 독자를 명확히 했다.
2. **실사용 사례 추가** — 홈서버 `couple` 프로필 세션 DB에서 확인한 이사 준비 조사(자격 확인·대출 비교·보증금 계산) 흐름을 4단계로 추가하고, Skill 목록 나열 단계는 사례로 교체했다.
3. **프로필 placeholder 구체화** — `<새-프로필>`을 사용자가 지정한 `failmy_bot`으로 치환했다.
4. **실사용 사례 상세화** — SNS/블로그 공개를 전제로, 세션 DB 원문을 다시 확인해 7단계(문서 판정·소득계산·대출여력·재계산·월세 시뮬레이션·자금 캘린더·시나리오 비교)로 확장하고, "비서가 실제로 한 일 3가지" 요약을 추가했다. 실명·정확한 금액은 이번에도 제외했다.
5. **그룹 개입 제한 절차 추가** — 부부 대화에 봇이 끼어드는 문제를 실제로 어떻게 해결했는지(`require_mention` 등 config, 리액션 설정, 게이트웨이 재시작 필요성)를 새 단계로 반영했다.
