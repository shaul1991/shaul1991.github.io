- 편집자: 한결
- 평가일: 2026-08-14
- 대상: `기억이 이어지는 개인 AI` 시리즈 6편
- LocalMind 확인: 개인 정본 brain, 읽기 전용 검색
- 저장소 노출 확인: 공개 저장소
- 최종 판정: **승인**

## 편집 절차

저장소 규칙에 지정된 `blog-editor` 스킬은 설치 목록에 없었다. Skills Hub의 동명 community 스킬을 검사했지만 Hermes 보안 스캐너가 위험 판정으로 설치를 차단했다. 이 판정을 우회하지 않고, 저장소의 정본인 `docs/blog-editor.md`에 정의된 한결의 역할과 평가 기준을 적용했다.

## 공개 근거 범위

LocalMind 기록과 현재 저장소에서 다음 내용을 교차 검증했다.

- LocalMind가 사람이 소유한 Markdown 기록에서 필요한 맥락을 검색하는 구조.
- `whoami`, `brief`, `search_notes`, `capture_note` 네 MCP 도구의 역할.
- 결정을 선택, 이유, 전제의 세 층으로 남기고 변동성이 큰 전제를 재검증하는 규약.
- 하나의 지식 정본과 기기별 로컬 실행 환경을 분리하는 운영 원칙.
- 저장소, 세션, 캐시, 자격증명을 각 실행 기기 경계에 두는 원칙.
- Hermes 프로필로 설정, 세션, 스킬, 메모리를 분리하고 사용자 진입점과 내부 작업자의 권한을 구분하는 구조.
- 원격 기기 접근은 사용자가 허용한 범위에서 수행하고 업무 코드·로그·고객 정보를 개인 LocalMind에 자동 저장하지 않는 경계.

공개 저장소에는 실제 호스트명, 사설 주소, 포트, 로컬 경로, 토큰, 계정 식별자, 비공개 저장소와 회사 운영 정보를 넣지 않았다. 공개 원고는 비공개 운영 정본을 복사하지 않고 개념 중심으로 다시 작성했다.

## 독자가 답을 얻을 질문

| 순서 | 글 | 독자의 질문 |
| --- | --- | --- |
| 1 | 왜 AI의 기억을 모델에게 맡기지 않았나 | 대화 기억만으로 왜 부족하고 기억의 정본을 어디에 둬야 하는가 |
| 2 | 다시 판단할 수 있는 기록은 무엇이 다른가 | 다음 AI가 재판단하려면 결정에 무엇을 남겨야 하는가 |
| 3 | Hermes는 언제 LocalMind를 찾고 기록하나 | 한 요청에서 검색, 검증, 실행, 기록이 어떻게 이어지는가 |
| 4 | 지식은 중앙에, 실행은 저장소가 있는 기기에 | 여러 기기에서 지식과 실행을 왜 분리하는가 |
| 5 | 에이전트에게 어디까지 보여주고 맡길 것인가 | 역할과 권한, 개인·업무 데이터 경계를 어떻게 나누는가 |
| 6 | 연결보다 먼저 검증해야 할 것들 | 연결 후 무엇을 실제 증거로 확인해야 하는가 |

## 최초 평가와 수정

최초 판정은 **수정 필요**였다. 4편이 모든 기기의 실행 주체를 Hermes로만 표현해 실제 구조보다 넓게 일반화했다. 이를 `Hermes와 로컬 실행 도구`로 고쳐, LocalMind의 공통 지식 계층과 각 기기의 다양한 실행 주체를 구분했다. 공개 문서에 불필요한 운영 세부 표현도 줄였다.
